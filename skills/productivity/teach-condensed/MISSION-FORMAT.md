# MISSION.md Format

Root `MISSION.md` — _reason_ user learns. Every teaching decision traces here.

## Template

```md
# Mission: {Topic}

## Why
{1-3 sentences. The concrete real-world goal the user is chasing. What changes in their life or work when they have this skill? Avoid abstract framings like "to understand X" — push for the underlying outcome.}

## Success looks like
- {A specific, observable thing the user will be able to do}
- {Another specific thing}
- {…}

## Constraints
- {Time, budget, prior commitments, learning preferences, anything that bounds the approach}

## Out of scope
- {Adjacent topics the user explicitly does not want to chase right now — protects the zone of proximal development}
```

## Rules

• **One mission per workspace.** Two unrelated topics → two workspaces.
• **Concrete over abstract.** "Run a half marathon by October" beats "get fitter."
• **Push back on vagueness.** Can't articulate why → interview before writing. Bad mission worse than none.
• **Revise when reality shifts.** Update file; don't leave stale mission steering sessions.
• **Keep it short.** Past one screen → compass became plan.

Move issues through triage role state machine on the project issue tracker.

Every comment or issue posted during triage **must** start with:

```
> *This was generated by AI during triage.*
```

## Reference docs

- [AGENT-BRIEF.md](./AGENT-BRIEF.md) — durable agent briefs
- [OUT-OF-SCOPE.md](./OUT-OF-SCOPE.md) — `.out-of-scope/` knowledge base

## Roles

**Category** (one each):

| Role | Meaning |
|------|---------|
| `bug` | Something broken |
| `enhancement` | New feature or improvement |

**State** (one each):

| Role | Meaning |
|------|---------|
| `needs-triage` | Maintainer needs to evaluate |
| `needs-info` | Waiting on reporter |
| `ready-for-agent` | Fully specified, AFK-ready |
| `ready-for-human` | Needs human implementation |
| `wontfix` | Will not be actioned |

Every triaged issue: exactly one category + one state. Conflicting state roles → flag and ask maintainer before anything else.

Canonical role names — actual label strings may differ. Mapping should have been provided — run `/setup-matt-pocock-skills` if not.

**Transitions:** unlabeled → `needs-triage`; then → `needs-info`, `ready-for-agent`, `ready-for-human`, or `wontfix`. `needs-info` → `needs-triage` when reporter replies. Maintainer can override — flag unusual transitions and ask first.

## Invocation

Maintainer invokes `/triage` in natural language. Examples: show attention items, look at #42, move #42 to ready-for-agent, what's ready for agents.

## Show what needs attention

Query issue tracker; three buckets, oldest first:

1. **Unlabeled** — never triaged
2. **`needs-triage`** — evaluation in progress
3. **`needs-info` with reporter activity since last triage notes** — re-evaluate

Show counts + one-line summary per issue. Let maintainer pick.

## Triage a specific issue

1. **Gather context** — full issue (body, comments, labels, reporter, dates); parse prior triage notes; explore codebase via domain glossary + ADRs; read `.out-of-scope/*.md`, surface prior rejections that resemble this issue
2. **Recommend** — category + state with reasoning + brief codebase summary. Wait for direction
3. **Reproduce (bugs only)** — before grilling: read steps, trace code, run tests/commands. Report: successful repro + code path, failed repro, or insufficient detail (`needs-info` signal). Confirmed repro → stronger agent brief
4. **Grill (if needed)** — run `/grill-with-docs`
5. **Apply outcome:**
   - `ready-for-agent` — agent brief comment ([AGENT-BRIEF.md](./AGENT-BRIEF.md))
   - `ready-for-human` — same structure; note why not delegable (judgment, external access, design, manual testing)
   - `needs-info` — triage notes (template below)
   - `wontfix` (bug) — polite explanation, close
   - `wontfix` (enhancement) — write `.out-of-scope/`, link from comment, close ([OUT-OF-SCOPE.md](./OUT-OF-SCOPE.md))
   - `needs-triage` — apply role; optional comment if partial progress

## Quick state override

"Move #42 to ready-for-agent" → trust maintainer, apply directly. Confirm (role changes, comment, close), act. Skip grilling. If `ready-for-agent` without grilling → ask whether to write agent brief.

## Needs-info template

```markdown
## Triage Notes

**What we've established so far:**

- point 1
- point 2

**What we still need from you (@reporter):**

- question 1
- question 2
```

Capture grilling resolutions under "established so far". Questions must be specific and actionable — not "please provide more info".

## Resuming a previous session

Read prior triage notes; check if reporter answered outstanding questions; present updated picture. Don't re-ask resolved questions.
